# 试卷图谱：从 PDF 到可交互解析网页

## 适用场景

用户给出一份或几份考试真题（通常是扫描版 PDF），要求：

- 做出**详细解析**（有公式、有推导、有计算过程）
- 做成**能点开、能标记进度**的网页，而不是一段文字
- 分析**考点频率、重复率**，给出**复习优先级**
- 对**重难点单独深挖**（配图、逐量标注）

不适用：只需要口头答题、不需要成品的场景。

## 全流程

### 阶段 0 · 建项目与探 PDF

```bash
python scripts/init_project.py <项目目录> --title "《课程名》四套期末卷 交互解析"
python scripts/pdf_probe.py <项目目录>/pdfs/xxx.pdf --out <项目目录>/pdfs/imgs
```

`pdf_probe.py` 会判定文字版 / 扫描版：

| 判定 | 后续动作 |
|---|---|
| 文字版（字符数 > 200×页数） | 直接读导出的 `.txt`，逐页誊写题干 |
| 扫描版 | 导出 `p1.jpg…`，用多模态逐页读取 |

**扫描件读不清时**（这个环节决定答案对错，不能省）：

```python
from PIL import Image, ImageEnhance, ImageFilter, ImageOps
im = Image.open('p2.jpg').convert('L')
c = im.crop(box)                                   # 先整图定位，再局部裁
c = ImageOps.autocontrast(c, cutoff=1)
c = c.resize((c.width*5, c.height*5), Image.LANCZOS)
c = c.filter(ImageFilter.UnsharpMask(radius=4, percent=180, threshold=2))
c.save('zoom.png')
```

### 阶段 1 · 识题

1. **一页一页读，边读边誊成文本**，不要只记在大脑里（第 3 页的题可能与第 1 页共用条件）。
2. **表格、附图单独裁出来核对**——分值、给定数据、图上标号错一个，后面全错。
3. **图上字母标号必须放大确认**。低分辨率下 `b`/`c`、`a`/`b` 极易读反，读反会直接把公式写错。真实案例：再热循环的 `1→b→a→2` 被读成 `1→a→b→2`，整道填空题符号颠倒。

### 阶段 2 · 做题（本技能的核心）

**先独立解，不要依赖"标准答案"**——原卷通常不给答案。

每道题完成前必须过三关：

| 关卡 | 做法 |
|---|---|
| 数据关 | 题给数据逐个核对（尤其查表值：焓、熵、饱和参数） |
| 算法关 | 至少两条独立路径算同一个结果（如 η = w/q₁ 与 η = 1 − q₂/q₁；Π = T₀ΔS 与 Π = W_max − W_net） |
| 量纲关 | 单位、数量级是否合理（效率别超过卡诺值、干度别超过 1） |

**写解析的层级**（对应用户要"有公式有计算过程"）：

```
一句话答案（a 字段）
  → 思路（为什么这么做）
  → 分步算式（F(R`...`) 一条一行，带代入的数值）
  → 交叉验算（key 块，说明两条路径一致）
  → 易错点（warn 块）
```

### 阶段 3 · 结构化

数据格式见 `references/data-format.md`。要点：

- 一题一个对象 `{n, q, a, sol}`，`q` 可直接写 HTML
- 公式用 `` ${F(R`...`)} ``，**反斜杠必须单写**（`\rho` 而非 `\\rho`）
- 图用 `` ${dg('key','图注')} ``，图定义在 `DIAG.key`
- 表格用 `${TBL([表头],[行...])}`

### 阶段 4 · 作图

图的质量决定这份资料能不能用。硬性要求：

| 要求 | 检查方法 |
|---|---|
| 几何自洽 | 定熵线必须竖直、两相区等压线必须水平、陡缓关系正确 |
| 文字不溢出 | 运行 `verify.py`，它按字宽估算右边界 |
| 逐量标注 | 每个符号在图上有位置，图下有"符号 \| 名称 \| 单位 \| 图上哪一段"表 |
| 关键点落在正确区域 | 穹顶图里"湿蒸汽点"必须在两片饱和线之间，过热区必须在右支之外 |

画完必做**坐标自检**：读出每个点的 `(x,y)`，核对 `1→2` 是否真竖直（`x` 相同）、`2→3` 是否真水平（`y` 相同）。

### 阶段 5 · 构建与校验

```bash
python scripts/rebuild.py <项目目录>      # 数据 js → 内联进 HTML
python scripts/verify.py  <项目目录>      # 六项校验
```

`verify.py` 检查：结构计数 / 标签配对 / 模板残留 / 双反斜杠 / SVG 溢出 / 卡片渲染。

**六项全绿才算做完**，退出码 0。

### 阶段 6 · 统计（用户要"考点频率"时）

逐题打**一个**主考点标签，然后统计：

- 频次排行（条形图：`REBAR`）
- 卷 × 考点矩阵（热力图：`REMAT`，按行列最大值归一化，**不要用"合计"列做分母**）
- 跨卷重复题对照（哪些是"换皮重考"）
- 必背结论与公式清单（按考频排序）

### 阶段 7 · 专题（用户要"重难点讲解"时）

对高频或高难考点单独成卷，结构：

```
① 从零开始：这东西是干什么的
② 图怎么读（T-s / p-v / 示意图）
③ 公式怎么推（逐步，不跳步）
④ 两种约束下的结论对比（考试最容易翻车的地方）
⑤ 工程背景 + 易错清单
```

### 阶段 8 · 交付

`present_files` 打开成品。回复里给：卷数/题数、修过哪些错、关键结论表、以及**哪些题属于"口径题"需要按老师说法微调**。

## 质量控制红线

1. **不确定就标 ⚠，不要装作确定。** 教材口径有分歧的判断题，解析里并列写两种判法。
2. **"验证过"必须是真验证。** 心算一遍不算；要么跑脚本，要么两条路径都算出来。
3. **每个数值标明来源。** 查表值注明压力/温度；插值要说插值。
4. **修改答案要留痕。** 发现自己写错了，明确告诉用户改了什么、为什么改。
5. **图表"看起来对"不算对。** 一律用脚本量。

## 环境适配

- **Windows + Git Bash 下 `ls/grep/tail/head/dirname` 常常不可用**：所有文本处理改用 Python。
- `node` 路径会变（`~/.workbuddy/binaries/node/<version>/node.exe`），`verify.py` 已自动搜索。
- 脚本里的路径一律用绝对路径，不依赖 cwd。
